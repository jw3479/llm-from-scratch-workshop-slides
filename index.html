Notebook · §2.6 · RoPE homework recap

Say: “Both sentences contain the same words, but describe different events. In the first, Alice follows Bob. In the second, Bob follows Alice. A language model needs information about where words occur to interpret these relationships and predict what follows.”

When we first look up a token embedding, the same token starts with the same vector wherever it appears. A query–key dot product has no separate argument saying how far apart the tokens are. RoPE introduces explicit position information into those comparisons.

A query asks what information this position needs. A key describes what another position offers. Every token has both a query and a key in each head. RoPE means Rotary Position Embedding. Position means the token's index in the sequence, starting at zero, rather than a vocabulary token ID.

Mask distinction: The causal mask already provides some order information by restricting each position to its prefix. RoPE supplies explicit relative-position structure in the scores. Avoid claiming that a causally masked Transformer without RoPE cannot distinguish any word orders.

There are 128 model features and four attention heads in this notebook, giving 32 features per head. Group them as (0,1), (2,3), and so on, making 16 two-dimensional pairs. The figure illustrates just one pair. RoPE changes feature coordinates, not the order of the input tokens.

For pair i = 0,…,15, use angular frequency ωᵢ = Θ^(−2i/dₖ), with dₖ = 32 and Θ = 10,000 here. At position m, the angle is mωᵢ radians. The first pair rotates fastest. Later pairs rotate more slowly. The same frequency schedule applies to queries and keys in each head.

Rotation preserves each pair's length, so it also preserves the full vector norm. The angles follow a fixed formula. RoPE has no learned parameters, but gradients still flow through the rotated inputs to the learned query and key projections.

Turning two arrows by the same angle preserves the angle between them, their lengths, and therefore their dot product. The q and k here are the underlying content vectors for that one comparison. R(m) is a block-diagonal matrix that rotates every coordinate pair by its position-dependent angle. Multiplying R(m)q is a mathematical way to describe the elementwise cosine/sine code on the next slide.

Stay on slides · Trace the shapes, then the input/output contract on slide 13

Start with one sequence and one head. Q, K, and V each have shape (T,32). Every row contains one token's 32 features. We want a dot product for every query/key pair, so transpose K from (T,32) to (32,T). Then (T,32) @ (32,T) gives (T,T). Row i belongs to query i; column j belongs to key j. The dot product sums over the 32 features.

For T=5, there are five queries and five keys, giving 25 scores arranged as a 5×5 table. Scaling and masking preserve that shape. Mask future keys before softmax. Normalize across keys, the last axis, so each query's row of weights sums to one.

Now mix values. The weights have shape (T,T), while V is (T,32). Multiplying them sums over key positions and gives (T,32): one weighted value vector for each query. For five tokens, we get five output vectors, each containing 32 numbers.

Restore the leading axes. The same calculation happens separately for every sequence b and head h. Q/K/V and the mixed outputs have shape (B,4,T,32), while scores and weights have shape (B,4,T,T). B is the batch size and T is sequence length. K.transpose(-2,-1) swaps only sequence and feature axes, preserving batch and heads. The multi-head wrapper later transposes the output to (B,T,4,32), reshapes it to (B,T,128), and applies its learned output projection.

d_k is the query/key width per head, 32 here. Roughly independent unit-variance coordinate products produce dot products with standard deviation proportional to sqrt(d_k). Dividing by sqrt(d_k) controls score scale before softmax. The exercise uses Q.shape[-1] so its code also works for other widths. Key distinction: “We have calculated the loss. loss.backward() now follows the computation backward and calculates gradients for the learned parameters. Those gradients are available in each parameter’s .grad. The parameter values stay unchanged during this call. optimizer.step() then uses the gradients and its stored optimizer state to change the parameter values. The following forward pass uses the resulting weights. If the learning rate or update is zero, their numerical values can stay unchanged; optimizer.step() remains the stage that applies the update.”

Gradient meaning: A gradient gives the local rate of change of loss with respect to a parameter. Backpropagation applies the chain rule through the loss, vocabulary projection, Transformer blocks and embeddings. AdamW uses gradients together with running gradient statistics and weight decay to choose updates. A particular update is not guaranteed to reduce the loss on every batch.
